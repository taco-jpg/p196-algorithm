# Strict two-track folded-automaton certificate format

**PAPER PROOF (soundness); COMPUTED (all-length DFA product controls and integer tests).** This advances `AgentN07FoldedRegularSafety`: an alphabet of pair *sums* cannot distinguish a nonpalindrome with all-even pair coefficients from a palindrome having exactly the same coefficients. Therefore a fully general decimal safety invariant must track the two *ordered individual digits* at each folded position. This is a strictly more expressive certificate format, not a bounded-centre exclusion or a decimal infinite-orbit certificate.

## Strict expressivity witness

At step 8 of the ordinary reverse-and-add orbit from 196, `N=1067869`, with least-significant-first pairs `(9,1),(6,0),(8,6)` and centre digit `7`. Pair sums are `(10,6,14)`, ALL even. The palindrome `5377735` has pairs `(5,5),(3,3),(7,7)` and the SAME three pair sums and centre `7`. Hence every palindrome-free language defined solely by those summed coefficients must reject `1067869` if it includes all integer realizations of every accepted coefficient word; this is a proven limitation on coefficient-only invariants for this specific step, independent of width. The ordered-pair alphabet distinguishes the two words exactly.

## Finite transducer

Let the alphabet be `Sigma_b={0,...,b-1}^2` with outer-to-centre symbols `(a_i,z_i)=(d_i,d_{n-1-i})`, and a centre digit `c` when n is odd. Require the high digit of the first pair `z_0>0`. The palindrome condition is **exactly** `a_i=z_i` for EVERY pair, regardless of centre digit. Set `P_i=a_i+z_i`. For an input with m pairs, the low carries satisfy `l_0=0`, `l_{i+1}=floor((P_i+l_i)/b)`, `A_i=(P_i+l_i) mod b`. The upper carries are guessed in reverse spatial order, `r_i=floor((P_i+r_{i+1})/b)`, `Z_i=(P_i+r_{i+1}) mod b`, with `r_0=gamma` and boundary at the centre `r_m=l_m` when n even or `r_m=floor((2c+l_m)/b)` when n odd. In the latter case the new centre digit is `C=(2c+l_m) mod b`.

For gamma=0, output pairs `(A_i,Z_i)` and centre `C` if present. For gamma=1, output `(A_0,1)`, then `(A_i,Z_{i-1})` for i>=1; if n even the output centre is `Z_{m-1}`, otherwise the last pair is `(C,Z_{m-1})`. One-digit sources are handled directly. These formulas are exactly ordinary reverse-add arithmetic, so the mapping of folded words is a **synchronous finite-state rational relation** with a one-digit upper-track delay when the number gains a leading digit.

## Certificate soundness

A finite-state recognizer A accepts canonical two-track folded strings with their final parity and optional centre. It is a **sound decimal Lychrel certificate** for a given N if: (i) A accepts N; (ii) every accepted word has a mismatched pair `(a_i,z_i)`; and (iii) the full exact two-sided carry transducer maps A's language into A's language. By induction on reverse-add iteration, all iterates are accepted and thus nonpalindromic. Conditions (ii) and (iii) are each exact, decidable finite-state reachability properties, *without restricting any centre width or any length*. Unlike a pair-sum DFA, an automaton over individual digit pairs has the expressive power needed to describe **every** nonpalindromic decimal input; a small *closed* invariant remains unconstructed.

`two_track_certificate.py` implements full unbounded-length closure by BFS on the product of source/target DFA, low/high carry bits, previous upper digit, leading-pair flag and optional mismatch-witness flag. The prototype DFA supports parity-specific accepting states but allows all middle digits at an accepting state; allowing centre-dependent accepting state sets is a straightforward extension and not implemented here. BFS returns a concrete counterexample when forward closure/safety fails; `None` is a sound graph-closure result. The `all_positive` DFA closes in every tested base but admits palindromes; the `mismatch` DFA excludes all palindromes but fails closure (e.g. decimal `10 -> 11`). No decimal certificate is claimed.
