## 原算法与边界是否保留

逐定义对照对象包括 `creative_regular_direct__8988fd8c6a0aad92.py` 的 `fst_graph` 与终端枚举、`persist_spacetime_weighted__d53dd1c09dcfc34a.py` 的 `TERMS`/`TS`/`history_path`，以及 `creative_regular_invariant__ea923cdb26a39825.py` 的 `C`/`D`/`valid`/`fold`/`trans`。完整基础的列和、进位、输出、宽度、规范实现等定义也在审查范围内。

以下容易遗漏的条件均保留：

1. 两个初态恰为 `(0,0,0,-1,false)` 和 `(1,0,1,1,false)`；`-1` 是真实 `Int` 哨兵，没有替换为零。
2. 首个 pair 必须正，所有 pair 至多 18；之后允许零 pair。初始高位进位与溢出标记一致，低位进位为零。
3. 中心只允许 `none` 或 0 到 18 的偶数；没有 pair 时中心必须存在且正。这排除了空字、单中心零和奇数中心，同时保留全部一位正数输入。
4. 偶数宽度终端要求两方向进位相同；奇数宽度终端要求中心列将低位进位推进到高位进位。
5. 无溢出时保留原宽度，奇数输入输出中心为计算中心数字的两倍；偶数输入没有中心。
6. 溢出时输出宽度增加一：偶数输入产生延迟数字的两倍作为中心；奇数输入必须追加最后一个 pair，并且输出没有中心。
7. `L=1` 对应零个 pair，但仍有合法终端。Boundary 模块以精确 iff 和无溢出/溢出两个实例直接核验该边界；`L=0` 被明确拒绝。

`State` 类型允许构造不可达状态，`emit` 在非法负延迟溢出状态上使用 `Int.toNat`，因此并未声称任意 `State` 都与 Python 整数状态逐点相等。正式语义限定在合法初态的有限转移可达图或完整接受路径上。`Reachable` 正是这些初态与 `Transition` 的有限闭包，`reachable_iff_mem_states` 已把它精确等同于原 46 状态列表。
